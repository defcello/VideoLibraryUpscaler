Read-only inspection of `pipeline.db` identified two failed jobs. No jobs were
retried or modified during diagnosis; the server must be restarted to load the
code changes.

## Zorro — 0b8b799ade35

At 01:16:36 local time, ffmpeg failed writing the deinterlaced MP4 with
`No space left on device`. The last output size was 4,194,048 KiB, immediately
below 4 GiB. A Windows volume query confirmed R: is FAT32 and Z: is NTFS.
This is consistent with hitting FAT32's single-file ceiling. Free disk space
alone cannot detect this condition. VSPipe's subsequent errno 32 broken pipe
masked the encoder error in the job's failure summary.

New ingest selection rejects FAT/FAT32 and refuses to fall back to an
unsuitable/full drive. Stage dispatch also checks existing job inputs so an
old R: staging location is rejected before more processing. Piped failures
now include both errors, with the encoder error first, enabling disk-full
classification. Existing R: jobs need re-staging on NTFS/exFAT before retry.

## Pilot — 12ca8742e17e

At 00:39:49 local time, Topaz reported `torch.OutOfMemoryError`: a 3.09 GiB
allocation failed, with 6.57 GiB reported free, 13.18 GiB allocated by PyTorch,
and 2.98 GiB reserved but unallocated. Resolve was not running, per the user.
The figures support fragmentation/allocator pressure as an explanation, but
the logs do not isolate the precise driver or allocator mechanism.

Segment 0 (through 48.15 seconds) was checkpointed successfully despite the
known recoverable QSV post-processing error. Segment 1 spanned 1,294.5 seconds;
only 112.1 seconds of output survived. The initial 19 GiB allocation check did
not prevent this later OOM. The existing expandable-segments environment
setting was already present; adding it again would not fix this failure.

Segmentation remains restricted to detected black-frame scene changes, so no
arbitrary duration cap can introduce a seam inside a scene. Successful VRAM
allocation checks are now logged with their inference-time limitation, and
actual OOM errors propagate instead of being replaced by a truncated-output
error. The allocation probe cannot predict fragmentation or allocator pressure
that develops later inside a long scene.
